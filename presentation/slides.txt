# What Is a Container?
 
A container is a self-contained package that includes:
 
- A deployed application
- All required dependencies
- Configuration required to run the application
 
Benefits:
 
- Consistent deployments
- Portable across environments
- Fast startup times
- Efficient resource usage
 
Containers typically run:
 
- On servers
- In data centres
- In cloud environments

# Creating Your Own Image
 
## Preparation
 
Before building:
 
1. Gather application artifacts
2. Create a dedicated build directory
3. Document prerequisites
4. Document installation steps
5. Create a Dockerfile
 
Example directory:
 
```text
project/
├── app.jar
├── config.yml
└── Dockerfile
```
 
---
 
# Dockerfile Example
 
```dockerfile
FROM eclipse-temurin:21
 
WORKDIR /app
 
COPY app.jar .
 
EXPOSE 8080
 
CMD ["java", "-jar", "app.jar"]
```
 
## What This Does
 
- Downloads a Java runtime image
- Sets the working directory
- Copies the application
- Exposes a port
- Starts the application
 
---
 
# Build the Image
 
## Command
 
```bash
docker build -t myapp .
```
 
## What Happens
 
Docker:
 
1. Reads the Dockerfile
2. Builds image layers
3. Creates a reusable image
4. Stores it locally
 
Result:
 
```text
myapp:latest
```

# Run a Container
 
## Command
 
```bash
docker run -d \
-p 80:3000 \
--name myapp \
myapp
```
 
## Explanation
 
- `-d` = detached mode
- `-p` = port mapping
- `--name` = container name
- `myapp` = image name

# Publishing Container Images
 
## Why Publish?
 
To allow:
 
- Other users
- Other servers
- Kubernetes clusters
 
to pull and run your image.
 
Common registries:
 
- Docker Hub
- GitHub Container Registry
- Azure Container Registry
- AWS ECR
 
---
 
# Publishing Example
 
## Login
 
```bash

```
 
## Tag Image
 
```bash

```
 
## Push Image
 
```bash

```

# Kubernetes
 
## What Is Kubernetes?
 
Kubernetes is:
 
- A container orchestration platform
- A container runtime platform
- The backbone of many cloud-native deployments
 
Responsibilities:
 
- Scheduling workloads
- Scaling applications
- Self-healing failures
- Service discovery
- Rolling updates
 
---
 
# Why Kubernetes?
 
Without Kubernetes:
 
- Manual deployments
- Manual scaling
- Single points of failure
 
With Kubernetes:
 
- Automated deployments
- High availability
- Automatic recovery
- Horizontal scaling

# Example Manifest
 
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
name: myapp
spec:
replicas: 2
selector:
matchLabels:
app: myapp
template:
metadata:
labels:
app: myapp
spec:
containers:
- name: myapp
image: myuser/myapp:1.0
```
 
---
 
# Example Service
 
```yaml
apiVersion: v1
kind: Service
metadata:
name: myapp
spec:
selector:
app: myapp
ports:
- port: 80
targetPort: 3000
type: LoadBalancer
```
 
---
 
# Deploying to Kubernetes
 
Apply manifests:
 
```bash
kubectl apply -f deployment.yaml
kubectl apply -f service.yaml
```
 
Check resources:
 
```bash
kubectl get pods
kubectl get services
```
